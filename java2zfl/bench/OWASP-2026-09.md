# java2zfl against the OWASP Benchmark for Java (2026-09-27)

What `java2zfl` answers on the OWASP Benchmark v1.2 (2 740 servlets; `expectedresults-1.2.csv` labels each as a real
vulnerability or not, by category and CWE). It is measured the way `php2zfl` was measured against SARD
(`php2zfl/bench/sard.py`, `dataset/sard/README.md`). There are three verdicts, **OPEN is an abstention** (never a
hit and never a miss), and **every disagreement is classified**, with UNCLASSIFIED printed if a rule is missing.

**Nothing of the Benchmark is in this repository.** It is GPL-licensed, so the harness reads a clone in place.
This report names test cases, their expected label, our verdict and our notes, and nothing else.

## Instrument and commands

- Instrument: introspect `d675028` (this branch's base), `java2zfl/java2zfl.py` **unchanged**.
- Parser: `javalang` 0.13.0, the dependency java2zfl's README names. It was absent in the measuring container
  and was installed from PyPI with the curator's approval. It was the only download besides the Benchmark.
- Corpus: `OWASP-Benchmark/BenchmarkJava` at `20cbf3d`. No JDK is needed: java2zfl parses the source and does
  not compile it. No network, no API keys.

```bash
git clone --depth 1 https://github.com/OWASP-Benchmark/BenchmarkJava.git /tmp/owasp
pip install javalang
python3 java2zfl/bench/owasp.py /tmp/owasp                        # sections 1-8 below (~5 min; --no-stock-check: ~1 min)
python3 java2zfl/bench/owasp.py /tmp/owasp --project              # + section 9, the whole-project run
python3 java2zfl/bench/owasp.py /tmp/owasp --list --json rows.json   # + one line per disagreement / every row
```

**How a file is judged.** Each test file is analysed with the Benchmark's 15 helper classes in view: the
helpers are indexed first, then the test file, which is then judged. The file's verdict for its category is
the worst sink of that category's context, in the order REFUTED > OPEN > EARNED > NONE.
- **EARNED:** the engine reached a sink of the context and judged it clean.
- **NONE:** no sink of the context was recognised at all.

java2zfl prints only REFUTED and OPEN, so to a user EARNED and NONE look alike: silence. The harness still
separates them, because EARNED is a verdict the engine reached.

The harness never edits the analyzer. It runs a subclass that only observes: it keeps the EARNED dispositions
the engine computes and then drops, and it snapshots or forces the taint environment before chosen statements.
A self-check asserts that the subclass's REFUTED/OPEN output **equals the stock engine's on every one of the
2 740 files**.

- **hit:** vulnerable → REFUTED
- **miss:** vulnerable → EARNED or NONE (nothing flagged)
- **false alarm:** safe → REFUTED
- **abstention:** OPEN, with either label

## 4. Every miss, classified (518; UNCLASSIFIED: 0)

Every Benchmark case has one shape: a **source** puts request data into `param`, a **propagator** turns
`param` into `bar`, and a **sink** uses `bar`. The harness finds where java2zfl loses the flow with three
counterfactuals on the unchanged engine:
- **SOURCE lost:** `param` is not T where propagation starts.
- **PROPAGATION lost:** with `param` forced to T there, `bar` is still not T where the sink part starts.
- **SINK lost:** with `bar` forced to T there, no sink of the context is REFUTED.

A miss is classified by the **first** stage it loses. Every miss loses at least one stage; a miss that lost
none would be printed as UNCLASSIFIED, and there are none. The named source, propagator and sink come from
signatures read in the test's source.

### SOURCE lost first: 398

| n | sqli | cmdi | xss | source | `param` | why |
|--:|--:|--:|--:|---|:-:|---|
| 83 | 44 | 13 | 26 | `getQueryString()` then `substring` + `URLDecoder.decode` | Z | `substring` and `decode` are unknown calls |
| 67 | 33 | 13 | 21 | `getParameterNames()` (the parameter *name*) | Z | `Enumeration.nextElement()` is an unknown call |
| 60 | 27 | 14 | 19 | `getParameterMap()` then `Map.get(..)[0]` | Z | `Map.get` is an unknown call |
| 59 | 21 | 15 | 23 | `getHeader(..)` + `URLDecoder.decode` | Z | `decode` is an unknown call |
| 49 | 17 | 11 | 21 | `SeparateClassRequest.getTheParameter(..)` (the request read inside a helper) | **F** | the summary records param→return only; a call with a literal argument reads **clean**, although it returns request data |
| 44 | 19 | 11 | 14 | `getHeaders(..).nextElement()` + `URLDecoder.decode` | Z | unknown calls |
| 36 | 25 | 11 | 0 | `getCookies()` loop, `Cookie.getValue()` + `URLDecoder.decode` | Z | unknown calls |

Only 2 of the Benchmark's 9 source shapes arrive as T: `getParameter` and `getParameterValues(..)[0]`. The
contract (INTROSPECT-SEMANTICS §3) asks every module for a catalog of **transparent transformers**, such as
decode, `.get` and `.read`, that preserve taint. java2zfl's catalog has none, so every library call on the way
turns T into Z.

### PROPAGATION lost first: 104

| n | sqli | cmdi | xss | mechanism in java2zfl |
|--:|--:|--:|--:|---|
| 41 | 17 | 8 | 16 | **inner-class call** (`new Test().doSomething(..)`). javalang attaches the call to the constructor as a selector. java2zfl reads the constructor, which has no arguments, as **F** and never applies the method's summary. | 20 | 7 | 2 | 11 | **interface call** (`thing.doSomething(..)`). Summaries are keyed by bare method name. The bodiless `ThingInterface.doSomething`, indexed after Thing1/Thing2 (or the test's own `doSomething`), wins, and its empty summary reads **F**. The implementation is picked at run time by reflection in ThingFactory. |
| 25 | 12 | 9 | 4 | **template inside a private method** (Base64 round trip 7, ArrayList 6, ternary 5, switch 3, HashMap 2, split 1, StringBuilder 1). The template yields Z (or F), and a summary records only **T** returns, so the call reads **F**, not Z. |
| 6 | 2 | 1 | 3 | **switch statement, inline.** `SwitchStatement` is not walked, and `String bar;` with no initializer is **F**. |
| 12 | 5 | 1 | 6 | **inline unknown call or expression**, which gives Z: ArrayList `get` 4, HashMap `get` 4, ternary 2 (`TernaryExpression` is not modelled), `split` 1, StringBuilder 1. |

## 9. The whole-project run (introspect.py's way)

This run is `java2zfl.analyze_app` over all 2 766 `.java` files under `src/main/java` in one go, which is
exactly what `introspect.py` does. The stock output has no EARNED, so "silent" below means neither REFUTED
nor OPEN.

| category | label | REFUTED | OPEN | silent | Benchmark scoring |
|---|---|--:|--:|--:|---|
| sqli | vulnerable | 14 | 29 | 229 | TPR 5.1, FPR 3.0, score 2.1 |
| sqli | safe | 7 | 26 | 199 | |
| cmdi | vulnerable | 6 | 12 | 108 | TPR 4.8, FPR 4.0, score 0.8 |
| cmdi | safe | 5 | 18 | 102 | |
| xss | vulnerable | 11 | 73 | 162 | TPR 4.5, FPR 2.4, score 2.1 |
| xss | safe | 5 | 67 | 137 | |
| **all** | | 31 hits | | | **TPR 4.8, FPR 3.0, score 1.8** |

The project run is *better* than the per-case run for the wrong reason. Exactly **32 cases** differ, and every
one routes its flow through a private method `doSomething`:
- 19 vulnerable cases move from silent to REFUTED;
- 12 safe cases move from silent to REFUTED;
- 1 safe case moves from silent to OPEN.

Summaries are keyed by bare method name, so every call to `doSomething` in the project uses the summary of
the **last file indexed**, `BenchmarkTest02740.java`, whose body passes its argument through. Each servlet's
verdict is therefore decided by an unrelated file. Rename or reorder that file and these 32 verdicts move.
This is §4's interface-call collision at project scale, and it is the receiver-aware rule of
INTROSPECT-SEMANTICS §4 ("never match … by bare method name") still unmet for *summaries*.

## 10. A contract finding: EARNED on unverified flows

INTROSPECT-SEMANTICS §1: *"When unsure, emit OPEN — never downgrade an unverified flow to EARNED."* On
**293** vulnerable cases the engine's verdict at the real sink is EARNED, and on 258 safe cases it is EARNED
too. The first is a clean verdict on a flow the engine never verified. Five mechanisms turn "unknown" into F:
1. a summary records only T returns, so any other return, Z included, reads F;
2. a bodiless (interface) method gets an empty summary, so its calls read F;
3. `new C().m(..)` is read as `new C()`, which reads F;
4. a local declared without an initializer reads F, and a `switch` that would assign it is not walked;
5. a collection created empty reads F, and `add(..)` is not tracked.

java2zfl does not print EARNED, so a user sees silence rather than a false "clean". The disposition is
computed all the same, and a caller that consumed it would be told "clean".

## 11. How mature the analyzer is

On this benchmark java2zfl is an **early prototype**: its verdict layer is sound in form, but its dataflow and
catalogs are far too thin for the Benchmark's code.
- **Recall.** In the per-case run it finds 12 of 644 real vulnerabilities (TPR 1.9%) at FPR 0.9%, a Benchmark
  score of 1.0, which is on the guessing line. The whole-project run scores 1.8, and only by accident (§9).
- **Precision.** 5 of its 17 alarms are false (29%), and 17 of 48 in the project run. Each of the per-case 5
  comes from not evaluating a constant condition. The benchmark is not at fault: its labels hold wherever they
  can be checked (§7).
- **Where the flow is lost.** At every stage at once, not at one weak link: 430 of the 518 misses lose two or
  three stages, so no single catalog entry moves the score much.
- **Soundness.** The engine turns "don't know" into "clean" in five places (§10), which its own contract
  forbids.
- **Stability.** Its summaries are keyed by bare method name, so a project run's verdicts depend on which file
  was indexed last (§9).

The earlier calibration (0 false positives on spring-petclinic, 6/6 on java-sec-code) measured the flows those
apps happen to contain. A labelled denominator shows how narrow that is.

**What would most raise recall**, by the counterfactual bounds in §5:
1. **Fix the summaries.**
   - Apply `new C().m(..)` as a call to `m`: that alone bears on 181 misses.
   - Resolve interface calls without letting a bodiless declaration win.
   - Make an unknown or partly-tainted return, an uninitialised local, and a walked `switch` yield **Z, not
     F**.

   The Z part is a soundness fix: it turns 293 false "clean" verdicts into honest OPEN. It raises recall only
   together with item 2, which turns Z into T.
2. Add a **transparent-transformer catalog**, which the contract already requires: `URLDecoder.decode`,
   `Enumeration.nextElement`, `Map/List.get`, `String.substring/split/toCharArray`, `Cookie.getValue`,
   StringBuilder, Base64, `new String(..)`. This turns the source column from Z to T.
3. Add the missing **sinks**: Spring `JdbcTemplate.*`, `prepareCall`, `addBatch`, `printf`/`format`,
   `ProcessBuilder.command`, and every argument of `exec`.

Together, source and propagation bound 210 recoverable misses, and all three bound 518. Two caveats:
- **Precision risk.** Items 1 and 2 alone would light up the dead branches: 310 safe cases carry a constant
  construct whose tainted branch is dead. Recall should rise together with **constant-condition evaluation**
  (the arithmetic `if`/ternary, a literal `switch`, index-precise lists). Otherwise the false alarms grow
  from 5 toward that 310.
- **Not modelled.** Path traversal, LDAP, XPath and trust-boundary are real taint categories with no sink
  context at all. Adding contexts is the other large lever, and it is outside this measurement.

## Method, stated plainly

- The counterfactual forces **one** variable to T before **one** statement on the unchanged engine. "Would
  recover" is an upper bound for a fix that makes that stage deliver T, not a promise that a given patch
  would. The stage boundaries are read from the AST: the statement after the last assignment of `param`, and
  the statement after the last assignment of `bar`.
- Helper-first indexing is the harness's choice for the per-case run. The whole-project run (§9) uses
  java2zfl's own `analyze_app` over the full source tree, in sorted path order.
- The false-alarm and label checks evaluate the Benchmark's constant constructs with integer arithmetic taken
  from the source. The source, propagator and sink names come from signatures, first match wins.
- `owasp.py` regenerates every number here. `--json` writes one row per test: name, label, verdict, the
  engine's records, and the class.
